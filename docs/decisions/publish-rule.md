# Decision: when a scored record may be published

**Status: decided.** It replaces the rule that a record may be published only while the
integration checkout's `HEAD` is the record's own `provenance.code.commit`. That rule cannot
hold once work happens on parallel checkouts.

## The rule

A record scored at commit `R` is publishable on `main` if

```
git diff --name-only R main -- src/ metadata/ tests/fixtures/snapshots/
```

prints nothing. In words: nothing that computes a figure, declares a source or supplies the panel's
inputs has changed between the commit that scored the record and `main`.

If anything under those paths has changed, the record is re-scored at a commit that satisfies the
rule before it is published. It is never published with an explanation instead.

## How a publish happens

A publish is a pull request. It adds the records together with every page rendered from them,
regenerated by `python scripts/emit_results.py` in the same commit. The records and their pages
cannot land separately, and the generated blocks are never hand-edited. CI must be green.

## Why these paths

`src/` computes every figure, `metadata/` declares the sources and their availability, and the
snapshot fixtures are the panel's inputs. A change anywhere else (documentation, CI configuration,
tests that do not touch fixtures) cannot move a published figure. Any change that could is caught
by `tests/test_generated_results.py`, which regenerates the pages from the committed records.
