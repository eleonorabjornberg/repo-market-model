## What this does not show

- It is development data. The imposed skills are simulated; the candidate's real skill is read only in the 'development skill, unscaled' column, and that column is a rate on a pool the simulation also resamples, not a forecast of the confirmation.
- The data-generating schemes resample 2018-2026 origins; a confirmation period unlike them (a regime the pool does not contain) is outside what any rate here says. The regime scheme moves between the five development regimes; nothing in it is a stress regime that was never seen.
- B2 stands in for the calendar climatology B2*, which is not built, and B4 is not built; adding a baseline lowers the pass rate.
- Rates carry the Monte Carlo error shown; the critical value comes from the bootstrap draws per data set stated above, not 50,000.
- Calendar first: the loss vectors are those of a candidate that reads calendar days at the target day on direct pairs; the baselines B1'* and B2 are the declared references. The study fits nothing through `repo_model.ml`, so no producer is registered.
